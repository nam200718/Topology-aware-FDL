\begin{abstract}
Personalized Federated Learning (PFL) addresses statistical data heterogeneity (Non-IID data) across decentralized edge devices. However, practical deployments are governed by the \textbf{Personalization Trilemma}---the fundamental trade-off between statistical personalization accuracy across diverse skew regimes, on-device memory and compute constraints, and worst-case client fairness. Existing PFL paradigms make rigid compromises across this trilemma: \textit{Global Consensus} methods degrade under severe statistical skew; \textit{Dual-Model Regularization} achieves robust personalization but doubles local memory footprint and per-batch training latency; \textit{Decoupled/Split-Head} methods remain parameter-efficient but can suffer representation collapse under homogeneous (IID) data, especially naive variants such as FedRep (FedBABU remains near FedAvg, Table~\ref{tab:main_benchmark}); and \textit{Clustered Topologies} lack on-device local head specialization.

In this paper, we propose \textbf{HEP} (\textit{Hierarchical Ensemble Personalization}), a parameter-efficient framework designed to navigate the multi-dimensional trade-offs of the Personalization Trilemma. HEP reconciles global consensus learning, cluster-level collaboration, and local edge specialization through a single shared-backbone 3-tier architecture ($\text{Root}$, $\text{Parent}$, $\text{Local}$). It dynamically balances training using an entropy-based label skew metric ($R_{skew}$), anchored binomial-style loss weighting, and active-class logit masking. To protect client privacy, HEP uses random-projection sketching for data-free cluster routing, with an optional local-DP Gaussian mechanism (formal $(\epsilon,\delta)$-DP on the clipped sketch, Table~\ref{tab:clustering_privacy}) and substantially mitigates gradient inversion by making reconstruction severely underdetermined ($64$ constraints vs.\ $3072$-dim input) while preserving clustering geometry.

Across diverse heterogeneity regimes, HEP demonstrates a Pareto-efficient operating profile across the Personalization Trilemma: it achieves top-tier personalization accuracy under extreme statistical skew while matching or slightly exceeding global consensus under homogeneous data (72.92\% vs.\ FedAvg 72.43\% IID), operates strictly within a single-backbone memory envelope at roughly half the per-batch memory/latency of dual-model approaches (Table~\ref{tab:hardware_footprint}), and improves worst-case tail-client fairness in most skewed regimes (e.g., +11.76\,pp over FedRep at moderate skew; competitive at extreme/IID where FedRep/CFL retain narrow leads, Table~\ref{tab:main_benchmark}). We additionally formalize the threat model boundary, demonstrate in-scope label fault containment without external heuristics, and report a negative result showing that server-side Byzantine filtering cannot substitute for architectural head isolation against gradient corruption on shared backbones. All design choices carry measured justifications, cross-backend reproducibility is verified, and all artifacts are publicly available.
\end{abstract}

\section{Introduction}

Federated Learning (FL) \cite{mcmahan2017communication} enables distributed edge devices to collaboratively train statistical models without centralizing private raw data. Despite its privacy benefits, deploying federated optimization in production edge systems reveals the \textbf{Personalization Trilemma}---a fundamental tension among three competing objectives:
\begin{enumerate}
    \item \textbf{Statistical Generalization \& Skew Resilience}: Maintaining high accuracy across diverse data distributions, ranging from extreme Non-IID label skew ($\alpha \le 0.05$) to uniform homogeneous (IID) partitions.
    \item \textbf{On-Device Hardware Constraints}: Operating within strict edge device budgets ($<150\text{ MB}$ Peak VRAM, minimal per-batch latency, and single-pass feature evaluation) without inducing out-of-memory faults.
    \item \textbf{Worst-Case Fairness \& Network Realism}: Ensuring that tail-decile (bottom 10\%) clients do not suffer convergence failure under sparse sampling ($C_p \le 0.20$) or intermittent network connectivity.
\end{enumerate}

As summarized in Table \ref{tab:pfl_taxonomy}, existing Personalized Federated Learning (PFL) paradigms navigate this trilemma with rigid structural compromises:
\begin{itemize}
    \item \textbf{Global Consensus FL (FedAvg, FedProx, SCAFFOLD)}: Optimizes a single consensus model across all clients \cite{mcmahan2017communication, li2020federated, karimireddy2020scaffold}. While hardware-efficient ($1\times$ model footprint), global models experience severe client drift and accuracy degradation when local data distributions diverge.
    \item \textbf{Dual-Model Regularization (Ditto, APFL)}: Concurrently trains a global model and a private personalized model coupled via L2 proximal penalties \cite{li2021ditto} or interpolation scalars \cite{deng2020adaptive}. While achieving high personalization accuracy, maintaining two complete model graphs doubles client VRAM and per-batch compute passes, creating deployment barriers on memory-constrained edge hardware.
    \item \textbf{Decoupled / Split-Head Paradigms (FedRep, FedPer, FedBABU, FedALA)}: Shares a global feature extractor and isolates private local classification heads \cite{collins2021exploiting, arivazhagan2019federated, oh2021fedbabu, zhang2023fedala}. While parameter-efficient, naive split-head models lack intermediate collaborative structure and experience substantial representation collapse under homogeneous (IID) data.
    \item \textbf{Clustered Topologies (Clustered FL)}: Groups clients into sub-networks based on gradient similarity \cite{sattler2020clustered}. However, standard clustered FL enforces flat FedAvg within each cluster, lacking on-device local head specialization and failing to protect individual tail clients.
\end{itemize}

Rather than viewing PFL as a binary choice between resource-heavy dual models and fragile split-head architectures, we propose \textbf{HEP} (\textit{Hierarchical Ensemble Personalization}), a lightweight framework that navigates the trade-offs of the Personalization Trilemma:
\begin{itemize}
    \item \textbf{Shared-Backbone Multi-Head Multiplexing}: Edge clients maintain a single shared convolutional backbone paired with three lightweight classification heads: a global $\text{Root}$ head, a cluster-level $\text{Parent}$ head, and a private $\text{Local}$ head. Feature representations are computed only once per batch.
    \item \textbf{Adaptive Loss Weighting \& Routing}: Automatically balances training across the three heads via an entropy-based label skew metric ($R_{skew,i}$), anchored binomial-style loss weighting, variance-adaptive cluster momentum ($\beta_{c,k}=V_k/(V_k+\|\Delta_k\|^2)$, $V_k$ intra-cluster variance, $\Delta_k$ mean update), and staleness-aware fallback routing ($\tau_0=4.0$ default; see Alg.~\ref{alg:hep}).
    \item \textbf{Privacy-Preserving Cluster Routing}: Compresses linear head updates via 64-dimensional random projection sketching ($m=64$, $40\times$ over $d_{head}=2560$) with optional local-DP Gaussian noise on the clipped sketch, substantially mitigating gradient inversion while preserving clustering geometry.
    \item \textbf{Intra-Cluster Effective Sample Support}: Aggregates $6\times$ effective support via cluster-level update pooling ($2000$ pooled samples per class vs.\ $333$ local under $\alpha=0.05$), mitigating local overfitting while preserving tail fairness (no raw sample pooling; statistical support through Parent aggregation).
\end{itemize}

\subsection{Global Consensus Federated Learning}
The canonical federated learning baseline is FedAvg \cite{mcmahan2017communication}, which aggregates local client updates via sample-weighted averaging. FedProx \cite{li2020federated} introduces a proximal regularization term to stabilize convergence under client drift, while SCAFFOLD \cite{karimireddy2020scaffold} utilizes control variates to correct gradient variance. However, these methods optimize a single global model, which fundamentally struggles when client data distributions diverge severely under statistical heterogeneity.

\subsection{Dual-Model Regularization Paradigms}
To decouple global consensus from edge specialization, dual-model architectures maintain two distinct model states per client. Ditto \cite{li2021ditto} optimizes a global model and a private local model coupled through an L2 proximal penalty $\frac{\lambda}{2} \|w_{local} - w_{global}\|^2$. APFL \cite{deng2020adaptive} learns an adaptive interpolation parameter $\alpha \in [0, 1]$ between global and local models. While effective, maintaining dual neural network graphs doubles on-device memory (VRAM) and requires two forward/backward passes per batch.

\subsection{Decoupled and Split-Head Personalization}
Split-head methods share a feature extractor while training separate classification heads. FedPer \cite{arivazhagan2019federated} and FedRep \cite{collins2021exploiting} alternate updates between the shared base and local heads. FedBABU \cite{oh2021fedbabu} updates only the representation body during federated rounds while fixing the classifier head, fine-tuning locally post-training. FedALA \cite{zhang2023fedala} adaptively aggregates local and global representations via element-wise attention. While parameter-efficient, naive 2-tier split-head models lack intermediate cluster coordination and suffer representation collapse under homogeneous IID data.

\subsection{Clustered Topologies and Hierarchical Structures}
Clustered FL \cite{sattler2020clustered} partitions clients based on cosine similarity of gradient updates, but enforces flat FedAvg within clusters without on-device head specialization. In contrast, HEP synthesizes clustered sub-network sharing with local and global head multiplexing, establishing a 3-tier hierarchy that reconciles all four paradigms.

\section{Methodology}

\subsection{System Architecture \& 3-Tier Multi-Head Model}

Let $N$ denote the number of participating edge clients. Each client $i \in \{1, \dots, N\}$ holds a private dataset $\mathcal{D}_i \sim P_i(X, Y)$ with $C$ classes and observed class subset $\mathcal{Y}_i \subseteq \{1, \dots, C\}$. Client $i$ maintains a single model $F(x; \theta, w_r, w_p, w_l)$ parameterized by a shared convolutional backbone $f_\theta(x) \in \mathbb{R}^d$, a global consensus $\text{Root}$ head $w_r$, a cluster-level $\text{Parent}$ head $w_{p(i)}$, and a client-private $\text{Local}$ head $w_{l,i}$. During training, feature representations $h = f_\theta(x)$ are extracted \textbf{once} per batch to produce three concurrent class predictions:
\begin{equation}
\label{eq:multi_head}
z_{root} = g_{w_r}(h), \quad z_{parent} = g_{w_{p(i)}}(h), \quad z_{local} = g_{w_{l,i}}(h)
\end{equation}

\subsection{Active-Class Logit Masking (ACLM)}

When client $i$ observes only a fraction of total classes ($|\mathcal{Y}_i| \ll C$), unconstrained loss computation across all $C$ classes pushes negative gradients onto unobserved categories, causing severe margin degradation. HEP introduces \textbf{Active-Class Logit Masking (ACLM)}, which restricts the cross-entropy denominator on Local and Parent heads strictly to observed classes $\mathcal{Y}_i$:
\begin{equation}
\label{eq:aclm}
\mathcal{L}_{CE}^{masked}(z, y) = -\log \left( \frac{\exp(z_y)}{\sum_{c \in \mathcal{Y}_i} \exp(z_c)} \right)
\end{equation}
Unobserved classes $c \notin \mathcal{Y}_i$ are masked during the backward pass by setting $z_c = -\infty$. The Root head remains unmasked across all $C$ classes to preserve global multi-class feature geometry.

\subsection{Entropy-Based Skew Metric \& Binomial Head Weighting}

Rather than tuning heuristic thresholds, HEP quantifies local label diversity using normalized Shannon entropy:
\begin{equation}
\label{eq:r_skew}
R_{skew,i} = \frac{\exp\big(H(p_i)\big) - 1}{C - 1} \in [0, 1]
\end{equation}
where $p_i$ is client $i$'s empirical class histogram and $H(p_i) = -\sum_{c} p_{i,c} \ln p_{i,c}$. When client $i$ observes a single class, $R_{skew,i} = 0$; when classes are uniformly balanced, $R_{skew,i} = 1$.

To balance optimization across the three heads, HEP computes loss weights $(\lambda_r, \lambda_p, \lambda_l)$ via anchored binomial-style weighting with a dynamic anchor floor $a_i = \max\left(\frac{1}{2K}, \frac{|\mathcal{Y}_i|}{C}\right)$ (default $K=3 \Rightarrow 1/(2K)\approx0.167$; the manuscript's $a=0.15$ is the fixed-anchor ablated baseline in Table~\ref{tab:ablation}, not the dynamic $a_i$):
\begin{equation}
\label{eq:binomial_weights}
\begin{aligned}
\lambda_{r,i} &= \frac{1}{Z_i} \big(a_i + (1-a_i) R_{skew,i}^2\big), \\
\lambda_{p,i} &= \frac{1}{Z_i} \big(2 R_{skew,i}(1-R_{skew,i})\big), \\
\lambda_{l,i} &= \frac{1}{Z_i} (1-R_{skew,i})^2
\end{aligned}
\end{equation}
where normalizer $Z_i$ ensures $\sum_k \lambda_{k,i} = 1$ (renormalized after anchoring; pure binomial $R^2,2R(1-R),(1-R)^2$ sums to $1$ only when $a_i=0$). Under uniform data ($R_{skew} \to 1$), weight concentrates on the Root head ($\lambda_r \to 1$); under moderate skew ($R_{skew} \approx 0.5$), the cluster Parent head receives peak weight ($\lambda_p \approx 0.45$ with $a_i\approx0.17$, $\approx0.45$--$0.50$ across the $a$ range); and under extreme skew ($R_{skew} \to 0$), compute focuses on the private Local head ($\lambda_l \to 1/(1+a_i)$) while retaining anchor $a_i$ to prevent backbone drift. Example $C=10,K=3$: $|\mathcal{Y}_i|=10\Rightarrow a_i=1.0,R\!\approx\!1\Rightarrow(\lambda_r,\lambda_p,\lambda_l)\!\approx\!(1,0,0)$; $|\mathcal{Y}_i|=5,R\!\approx\!0.44\Rightarrow a_i=0.5\Rightarrow(0.43,0.35,0.22)$ (unnormalized $0.60,0.49,0.31$ sum $1.40$); $|\mathcal{Y}_i|=2,R\!\approx\!0.11\Rightarrow a_i=0.20\Rightarrow(0.18,0.16,0.66)$ (unnormalized $0.21,0.20,0.79$ sum $1.20$). Note $|\mathcal{Y}_i|=10$ yields $a_i=1$ (full data support $\to$ Root-dominant, Parent/Local suppressed) — intended. Edge case: if $|\mathcal{Y}_i|=1$, $\mathcal{L}_{CE}^{masked}=0$ for Parent/Local (Eq.~\ref{eq:aclm} denominator $=$ numerator), so gradient flows only through the anchored Root term; all reported regimes have $|\mathcal{Y}_i|\ge 2$ after Dirichlet partitioning except pathological single-class clients where Local/Parent heads are inactive by design.

\subsection{Unified Training Loss and Ensemble Prediction}

Local mini-batch training minimizes the composite weighted loss:
\begin{equation}
\label{eq:composite_loss}
\mathcal{L}_{batch} = \lambda_{r} \mathcal{L}_{CE}(z_r, y) + \lambda_{p} \mathcal{L}_{CE}^{masked}(z_p, y) + \lambda_{l} \mathcal{L}_{CE}^{masked}(z_l, y)
\end{equation}
During inference, final predictions combine the three heads using inference ensemble weights $\alpha$ and an additive active-class mask:
\begin{equation}
\label{eq:inference_prediction}
z_{pred} = \alpha_r z_r + \alpha_p z_p + \alpha_l z_l + \mathbf{m}_i
\end{equation}
where $\mathbf{m}_i \in \{-\infty, 0\}^C$ masks unobserved classes ($m_{i,c}=0$ for $c \in \mathcal{Y}_i$ and $m_{i,c}=-\infty$ for $c \notin \mathcal{Y}_i$); unobserved logits are thus set to $-\infty$ after blending (additive, not multiplicative, to avoid undefined $0\cdot(-\infty)$ or sign flips). By default $\alpha$ mirrors the loss weights $\lambda$ ($\alpha_{r,p,l}=\lambda_{r,p,l}$), but can be dynamically adjusted during evaluation (e.g., via the mirror-descent-style update $\alpha\leftarrow\mathrm{softmax}(\alpha-\eta g)$ over inference weights, distinct from $\lambda$, described in Table~\ref{tab:clustering_privacy} and App.~\ref{app:reproducibility}) to downweight corrupted cluster logits ($\alpha_p\to0$). If a client experiences update staleness $\tau_i$ during partial participation, ensemble weights $\alpha_p,\alpha_l$ for \emph{both} Parent and Local heads attenuate exponentially toward the Root head via $e^{-\tau_i / \tau_0}$ with $\tau_0 = 4.0$ by default (effective $\tau_0 = \max(1, t / \text{participation\_count})$ when staleness history is available, approximating $1/C_p$; $C_p$ is the client participation fraction). The Local head remains on-device (always fresh), but its ensemble weight is faded together with Parent when the cluster context is stale, routing confidence to the global Root head (S-AFR, Alg.~\ref{alg:hep} and \S III.D). For high-cardinality regimes ($C\ge100$), HEP uses a two-stage intra-round schedule: an initial collaborative phase training backbone $+$ Root/Parent heads, followed by a frozen-backbone local-head specialization phase (see Appendix~\ref{app:reproducibility}).

\begin{algorithm}[t]
\caption{HEP Training Protocol at Round $t$}
\label{alg:hep}
\begin{algorithmic}[1]
\REQUIRE Datasets $\{\mathcal{D}_i\}_{i=1}^N$, Global backbone and root head $(\theta^{(t)}, w_r^{(t)})$, Cluster heads $\{w_{p,k}^{(t)}\}_{k=1}^K$, Local head states $\{w_{l,i}^{(t)}\}_{i=1}^N$.
\STATE Server broadcasts $\theta^{(t)}, w_r^{(t)}$ to all clients, and $w_{p,k}^{(t)}$ to cluster $k$.
\FOR{each client $i \in \{1, \dots, N\}$ \textbf{in parallel}}
    \STATE Compute label skew $R_{skew,i}$ (Eq. \ref{eq:r_skew}) and loss weights $(\lambda_r, \lambda_p, \lambda_l)$ (Eq. \ref{eq:binomial_weights}).
    \FOR{each batch $(X, Y) \sim \mathcal{D}_i$ across $E=5$ local epochs}
        \STATE Extract shared features $h = f_\theta(X)$ and compute logits $(z_r, z_p, z_l)$ (Eq. \ref{eq:multi_head}).
        \STATE Compute batch loss $\mathcal{L}_{batch}$ with ACLM (Eq. \ref{eq:composite_loss}) and update $(\theta, w_r, w_p, w_l)$ via SGD.
    \ENDFOR
    \STATE Generate 64-dim random projection sketch $s_i = P(w_{r,i} - w_r^{(t)}) \in \mathbb{R}^{64}$ (plaintext for routing; evaluated via update-similarity cosine in experiments).
    \STATE Upload sketch $s_i$ for cluster routing and $\text{SecAg}$-compatible aggregate $(\theta_i, w_{r,i})$ for global sync; per-cluster $w_{p,i}$ grouped by sketch routing (plaintext grouping in prototype; per-cluster SecAg requires partitioned masks/TEE, compatible but not yet implemented).
\ENDFOR
\STATE \textbf{Global Aggregation}: $\theta^{(t+1)}, w_r^{(t+1)} \leftarrow \sum_{i=1}^N \frac{|\mathcal{D}_i|}{|\mathcal{D}|} (\theta_i, w_{r,i})$ via SecAg-compatible weighted mean (prototype uses plaintext sample-weighted mean; cryptographically identical aggregate).
\STATE \textbf{Cluster Aggregation}: Assign clients to clusters via sketch cosine similarity; update cluster heads $w_{p,k}^{(t+1)} \leftarrow \beta_{c,k} w_{p,k}^{(t)} + (1-\beta_{c,k}) \sum_{i \in \mathcal{C}_k} \frac{|\mathcal{D}_i|}{|\mathcal{D}_{\mathcal{C}_k}|} w_{p,i}$ with variance-adaptive $\beta_{c,k}=V_k/(V_k+\|\Delta_k\|^2)$ (clamped $[0.1,0.9]$; see \S III.D), or $\beta_c$ when variance unavailable.
\end{algorithmic}
\end{algorithm}

\subsection{Privacy-Preserving Sketch Routing}

To prevent raw data or prototype leakage, cluster assignments are computed from parameter updates of the linear Root head $\Delta_i^{head} = w_{r,i}^{(t+1)} - w_r^{(t)}$. Clients compress this update into a 64-dimensional sketch $s_i = P \Delta_i^{head} \in \mathbb{R}^{64}$ using a shared random projection matrix $P$ (Johnson-Lindenstrauss, $40\times$ compression over $d_{head}=2560$), adding local differential privacy Gaussian noise $\mathcal{N}(0, \sigma^2 I)$ after $L_2$ clipping ($C_g=1.0$) when DP is enabled. The server assigns clusters by evaluating cosine similarity on these low-dimensional sketches, while the full model parameters $(\theta, w_r)$ are synchronized via SecAg-compatible aggregation \cite{bonawitz2017practical} (prototype aggregates plaintext sample-weighted means, cryptographically equivalent to SecAg; sketch is intentionally plaintext for routing). Per-cluster Parent aggregation $w_{p,k}$ is grouped by sketch similarity; a production per-cluster SecAg would require partitioned masks or a TEE per cluster, which is compatible but not yet implemented in the prototype. Reconstructing private images from 64 sketch constraints is severely underdetermined, substantially mitigating gradient inversion attacks (such as DLG \cite{zhu2019deep}) while preserving clustering geometry — ``preventing'' is used in the underdetermined linear-system sense, not as a formal guarantee against all adaptive attacks.

As detailed in Table \ref{tab:hardware_footprint}, dual-model regularization (e.g., Ditto) optimizes two independent neural network graphs per client, evaluating multiple global and personalized forward/backward passes per batch. While dual-model regularization achieves strong personalization, maintaining two complete model graphs introduces substantial memory and latency overhead on resource-constrained edge hardware.

In contrast, HEP trains on edge clients using a single model graph across $E=5$ local epochs per round. Because all three classification heads share the convolutional feature extractor $f_\theta$, heavy representations are computed only once per batch. Local backpropagation optimizes all active heads concurrently with loss weights $(\lambda_r, \lambda_p, \lambda_l)$ continuously calibrated by anchored binomial-style weighting. Under mild skew ($R_{skew} \to 1.0$), the schedule automatically concentrates loss gradients onto the global Root head ($\lambda_r \to 1.0$); under moderate skew ($R_{skew} \approx 0.5$), the cluster Parent head receives peak weight ($\lambda_p \approx 0.45$ with dynamic anchor $a_i\approx0.17$); and under extreme skew ($R_{skew} \to 0.0$), compute focuses on the private Local head while retaining a dynamic anchor $a_i=\max(1/(2K),|\mathcal{Y}_i|/C)$ to prevent backbone drift (the fixed $a=0.15$ is the static-grid ablation in Table~\ref{tab:ablation}/Appendix~\ref{app:reproducibility}). Continuous prediction weighting during inference is smoothly regulated by the ensemble blending mechanism.

\textbf{Compute Complexity of Parameter Analytics}: HEP eliminates empirical grid searches using lightweight closed-form analytics whose arithmetic complexity is negligible compared to backbone neural network operations. Computing the entropy skew $R_{skew,i}$ (Eq. \eqref{eq:r_skew}) consumes only $O(C)$ scalar operations per client on the local label histogram, while cluster sketch routing requires only $O(K \cdot m)$ scalar operations. In total, these analytics account for $< 0.01\%$ of backbone FLOPs, preserving the 8.35 ms / batch latency profile in Table \ref{tab:hardware_footprint}.

\textbf{Communication Cost Analysis}: In ResNet9 CIFAR-10, the shared convolutional feature extractor $\theta$ constitutes over 99.8\% of total network parameters (approximately 6.60 MB at 32-bit float precision), whereas each linear classification head $w$ contains only 2,570 parameters ($\approx$10.03\,KB at 32-bit) plus the $m=64$ sketch (256\,bytes), totaling $\approx$10.28\,KB (reported 10.25\,KB after rounding). The total uplink/downlink overhead is thus $<\!+0.16\%$ relative to FedAvg ($\approx$10.5\,KB with headers). For CIFAR-100 ($C=100$), the Parent head grows to $256 \times 100 + 100 = 25{,}700$ parameters ($\approx 102$\,KB), raising the worst-case overhead to approximately $+1.5\%$ of the 6.60\,MB backbone --- still negligible relative to the $2\times$ full-model duplication required by dual-model personalization. Methods compared use $E=3$ (FedAvg/FedPer/FedBABU), $E=5$ (FedRep, HEP), and $6$ effective passes (Ditto); see Tables~\ref{tab:hardware_footprint}--\ref{tab:main_benchmark} for ms/batch vs.\ wall-clock distinction.

We evaluate HEP across three distinct Byzantine attack vectors ($0\% \to 40\%$ malicious clients):
\begin{enumerate}
    \item \textbf{Label Flipping}: Attacking clients invert class labels $y_{att} = (C-1) - y_{true}$, causing targeted class confusion.
    \item \textbf{Sign Flipping}: Attackers scale gradient updates negatively: $\Delta_{att} = -2.0 \cdot \Delta_{true}$, pulling global consensus in the reverse optimization direction.
    \item \textbf{Gaussian Noise Poisoning}: Attackers inject zero-mean Gaussian perturbation $\mathcal{N}(0, 0.5^2)$ into parameter tensors.
\end{enumerate}

\textbf{Formal Threat Model Boundary ($\mathcal{T}_{\text{in-scope}}$ vs $\mathcal{T}_{\text{out-of-scope}}$)}:
To establish clear security guarantees, we formally partition the threat space:
\begin{itemize}
    \item \textbf{In-Scope Threat Model ($\mathcal{T}_{\text{in-scope}} = \mathcal{T}_{\text{statistical}} \cup \mathcal{T}_{\text{label}}$)}: Includes arbitrary statistical Non-IID label skew, class imbalance, sparse client sampling ($C_p < 1.0$), and malicious edge nodes executing semantic label-poisoning attacks ($y \to y_{att}$).
    \item \textbf{Out-of-Scope Threat Model ($\mathcal{T}_{\text{out-of-scope}} = \mathcal{T}_{\text{gradient}}$)}: Includes adversarial gradient-space manipulation (sign flipping, unconstrained gradient scaling) of shared feature extractors $\theta$ by compromised aggregation servers or rogue devices.
\end{itemize}

As detailed in Table \ref{tab:byzantine_multi_attack} and Fig. \ref{fig:byzantine}:
\begin{itemize}
    \item \textbf{Label-Space Fault Containment}: Under in-scope label-flipping attacks, FedAvg performance rapidly collapses to 16.65\% at $f=40\%$. In contrast, HEP maintains 71.58\% (+54.93\,pp over FedAvg, +8.71\,pp over Ditto) without requiring external filtering heuristics. Because label attacks corrupt classification margins rather than visual representations, isolating private Local heads $w_{l,i}$ and cluster Parent heads $w_p$ effectively shields clean edge devices from poisoned global predictions.
    \item \textbf{Single-Backbone Compute Efficiency vs. Dual-Model Isolation}: Under out-of-scope gradient attacks (sign-flipping), Ditto and HEP both suffer degradation due to corrupted latent representations on shared aggregations. However, Ditto consumes $2\times$ memory (217.15 MB vs 113.42 MB), evaluates 6 forward/backward passes per batch ($2.46\times$ FLOPs), and suffers out-of-memory (OOM) failures on resource-constrained microcontrollers. In contrast, HEP achieves superior label robustness (+8.71\,pp) and personalization (+0.70\,pp) while operating within a single-backbone footprint (113.42 MB, 1 pass for feature extraction), making it Pareto-efficient (no baseline dominates HEP on accuracy+memory+latency jointly) for physical edge devices.
\end{itemize}

\subsubsection{Why Server-Side Filtering Does Not Rescue Shared Backbones: A Negative Result}
\label{sec:negative_result}

A natural hypothesis is that Byzantine-robust server aggregation (Byzantine-resilient statistics applied to client updates) should restore HEP's sign-flipping tolerance without any client-side cost. We tested this hypothesis exhaustively under the Table~\ref{tab:byzantine_multi_attack} protocol ($\alpha=0.5$, $f=40\%$, seed 42) using three standard mechanisms, each gated behind configuration flags in our released engine:
\begin{itemize}
    \item \textbf{Coordinate-wise trimmed mean} at trimming depth $\beta \in \{0.2, 0.4\}$;
    \item \textbf{Soft-cosine trust weighting}: temperature-scaled softmax over cosine similarity of each update $\Delta_i$ to the unit-normalized centroid, with lower-quartile norm bounding against magnitude inflation;
    \item \textbf{Naive FedAvg} (baseline for comparison).
\end{itemize}

\textbf{Result.} No filter improved upon naive averaging. At $f=40\%$ (last-5-round personalized accuracy under the sign-flip protocol, $\alpha=0.5$, seed~42; cf.\ Table~\ref{tab:byzantine_multi_attack} sign-flip FedAvg $12.21\pm0.70\%$ which reports \emph{final-round} accuracy under the legacy 3-seed protocol): FedAvg 28.42\%, trimmed mean $\beta{=}0.2$ 28.27\%, soft-cosine trust 24.67\%, trimmed mean $\beta=0.4$ 23.06\%. Two failure mechanisms explain this:
\begin{enumerate}
    \item \textbf{Tail-splitting}: the sign-flip perturbation $\Delta_{att} = -c\,\Delta_{true}$ pushes attacker mass into \emph{both} tails of every coordinate distribution, so per-side trim depths below $f/2$ retain poisoned coordinates while deeper trims discard a majority of honest signal.
    \item \textbf{Centroid degradation under heterogeneity}: directional trust requires an honest centroid. As clients specialize under non-IID data, honest pairwise update similarities decay; once attacker mass approaches $\sim\!1/3$, the aggregate centroid norm collapses toward the uniform-trust fallback, silently re-admitting attackers.
\end{enumerate}

\textbf{Implication}. Ditto's sign-flip resilience stems from model \emph{isolation}, not aggregation filtering; no statistic computed over a shared-backbone update pool matched it. HEP therefore retains plain sample-weighted FedAvg as its default aggregator (all robust modes remain available as ablation flags), and we explicitly scope HEP's robustness claim to label-space fault containment ($\mathcal{T}_{\text{label}}$) --- where its head-isolation architecture dominates (71.58\% vs.\ FedAvg 16.65\% at $f=40\%$, +54.9\,pp; +8.7\,pp over Ditto, Table~\ref{tab:byzantine_multi_attack} protocol). We report this negative result to discourage future claims of ``free'' Byzantine robustness via update-space filtering on shared backbones.

\section{Discussion}

\subsection{The Personalization Trilemma and Multi-Paradigm Synthesis}
Our empirical and theoretical findings reveal that effective edge PFL cannot be formulated as optimizing a single isolated metric. Rather, federated deployment is governed by the \textbf{Personalization Trilemma}---the trade-off between statistical accuracy across heterogeneity regimes, on-device memory and compute constraints, and worst-case client fairness. As summarized in Table \ref{tab:pfl_taxonomy}, existing paradigms optimize at most two vertices: dual-model regularization (Ditto achieves accuracy/fairness at double cost; APFL less so at extreme skew), split-head (FedRep collapses IID while FedBABU is near FedAvg; see Table~\ref{tab:main_benchmark}), clustered FL lacks local personalization, and global consensus collapses under skew. HEP synthesizes these paradigms into a heuristic-free (no grid search; dynamic $R_{skew},a_i$) but not parameter-free (fixed $K,m, C_g$ etc., Appendix~\ref{app:reproducibility}) framework, providing a balanced operating profile across accuracy, resource efficiency, and tail fairness — Pareto-efficient in Table~\ref{tab:main_benchmark} in that no baseline dominates HEP on all axes simultaneously, though FedRep/CFL retain narrow fairness leads at extreme/IID.

\subsection{Privacy-Preserving Cluster Routing and Gradient Defense}
A critical requirement in edge federated deployments is that topology formation must operate without centralizing raw data, feature embeddings, or label distributions. HEP reconciles cluster formation with strict federated privacy through a two-channel architecture:
\begin{itemize}
    \item \textbf{Gradient Inversion Defense via Random Projection}: Projecting classification head updates $\Delta_i^{head} \in \mathbb{R}^{d_{head}}$ ($d_{head}=2560$) into an $m=64$ dimensional sketch ($s_i = P \Delta_i^{head}$) compresses the information exposed to the server to $64$ linear scalar constraints. Recovering a $3072$-dimensional input image from $64$ observations is severely underdetermined, substantially mitigating gradient matching attacks while preserving pairwise cosine clustering geometry.
    \item \textbf{Two-Channel Federated Communication}: The $m=64$ sketch $s_i$ is transmitted plaintext for server-side cluster routing, while full model parameters $(\theta_i, w_{r,i})$ are synchronized via SecAg-compatible aggregation \cite{bonawitz2017practical} (prototype uses plaintext sample-weighted means; per-cluster Parent aggregation is plaintext grouped by sketch — partitioned SecAg/TEE per cluster is compatible but not implemented, see \S III \& Alg.~\ref{alg:hep}).
    \item \textbf{Differential Privacy and Noise Resilience}: Adding Gaussian perturbation $\mathcal{N}(0, \sigma^2 I)$ to the clipped $m=64$ sketch yields client-level single-release budgets of $\epsilon_r = 96.9$ and $\epsilon_r = 48.5$ at $\sigma = 0.05$ and $\sigma = 0.10$. Even when strong noise ($\sigma = 1.00$, $\epsilon_r \approx 4.84$) collapses routing stability to $20\%$, downstream accuracy is protected by the adaptive ensemble routing mechanism, which dynamically concentrates inference weight on the private Local head ($\alpha_l \approx 0.95$, inference ensemble weight, vs.\ $\lambda_l$ loss weight) and anchored Root head, autonomously isolating noisy cluster assignments at a cost of only $-0.57$\,pp.
\end{itemize}

\subsection{Shared-Backbone Threat Model Scope vs. Dual-Model Edge Costs}
Our empirical findings in Table \ref{tab:byzantine_multi_attack} elucidate a fundamental architectural boundary:
\begin{itemize}
    \item \textbf{In-Scope Semantic Label Attacks ($\mathcal{T}_{\text{label}}$)}: Under label-flipping attacks ($f=40\%$), HEP achieves $71.58\%$ accuracy (+54.93\,pp over FedAvg, +8.71\,pp over Ditto, Table~\ref{tab:byzantine_multi_attack}) without external filters, because head isolation completely shields private classification hyperplanes from poisoned global labels.
    \item \textbf{Out-of-Scope Gradient Poisoning ($\mathcal{T}_{\text{gradient}}$)}: Under sign-flipping attacks, Ditto can achieve higher fault tolerance at low to moderate attack fractions because it maintains an unshared private model graph (Table~\ref{tab:byzantine_multi_attack}: Ditto 50.73\% vs.\ HEP 45.14\% at $f=10\%$, 53.50\% vs.\ 41.80\% at $f=20\%$), although HEP remains competitive and exceeds Ditto in the fresh $f=40\%$ sign-flip cell (23.60\% vs.\ 18.12\%). However, this isolation imposes a heavy price: $2\times$ memory (217.15 MB vs 113.42 MB), $2.46\times$ FLOPs, and out-of-memory crashes on memory-constrained edge devices. HEP delivers Pareto-efficient compute/memory trade-offs (undominated on accuracy+memory+latency) for standard edge deployments where physical nodes are authenticated.
    \item \textbf{Server-Side Filtering Is Not a Remedy}: We empirically rule out the standard counter-approach of replacing FedAvg with Byzantine-robust update statistics (trimmed means, directional trust weighting): under $f=40\%$ sign-flipping none outperformed naive averaging (Section~\ref{sec:negative_result}), because tail-splitting defeats rank filtering and honest-heterogeneity centroid decay defeats directional trust. Resilience on shared backbones must therefore come from architectural isolation properties.
\end{itemize}

\subsection{Class Cardinality, Partial Participation, and Scalability Bounds}
Our scalability analysis highlights the operational boundaries of multi-head federated architectures:
\begin{itemize}
    \item \textbf{High Class Cardinality ($C=100$)}: When class cardinality reaches $C=100$ under extreme skew ($\alpha=0.05$), edge clients observe narrow class subsets ($\le 6$ classes). Integrating Active-Class Logit Masking (ACLM), the entropy skew metric $R_{skew,i}$, and Two-Stage intra-round decoupling eliminates unobserved class negative gradients, allowing HEP to achieve 65.06\% personalized accuracy (+3.57\,pp over Ditto, +37.39\,pp over FedAvg) and 50.17\% worst-decile fairness (+2.80\,pp over Ditto).
    \item \textbf{Sparse Client Participation ($C_p=0.20$)}: By introducing staleness-aware routing and variance-adaptive cluster momentum ($\beta_{c,k}$), HEP resolves the cluster lag problem on infrequently sampled devices, stabilizing bottom-decile client accuracy under severe skew.
\end{itemize}

\subsection{Architectural Scope and Foundation Model (LoRA) Extensions}
While HEP is concretely evaluated on edge computer vision benchmarks (ResNet-9 and MobileNetV3), its three core architectural pillars are domain- and task-agnostic: (i)~\textit{3-Tier Shared-Backbone Multiplexing}, (ii)~\textit{Binomial Loss Scheduling}, and (iii)~\textit{Adaptive Ensemble Routing}. In large language model (LLM) deployments where full dual-model replication (e.g., duplicating an 8B-parameter Transformer) is completely infeasible on consumer edge devices, HEP maps directly to \textbf{Hierarchical Parameter-Efficient Fine-Tuning (PEFT)}: edge clients maintain a single frozen shared Transformer backbone paired with three lightweight LoRA adapter modules ($\text{Root LoRA}$ for global consensus, $\text{Parent LoRA}$ for domain/cluster specialization, and $\text{Local LoRA}$ for private edge personalization), with $R_{skew}$ evaluated via domain perplexity divergence.

\section{Conclusion}

We presented HEP (\textit{Hierarchical Ensemble Personalization}), a parameter-efficient, topology-aware hierarchical ensemble framework for personalized federated learning. HEP is heuristic-free (no grid search) but not parameter-free (fixed $K=3,m=64,C_g=1.0$ etc., App.~\ref{app:reproducibility}): it derives $R_{skew}$ via normalized entropy, dynamic anchor $a_i=\max(1/(2K),|\mathcal{Y}_i|/C)$, variance-adaptive $\beta_{c,k}=V_k/(V_k+\|\Delta_k\|^2)$, staleness $\tau_{0,i}$ ($4.0$ default, $\approx1/C_p$ when history available), and optional logit temperature via dispersion. Across five heterogeneity regimes on CIFAR-10, HEP demonstrates a Pareto-efficient operating profile across the Personalization Trilemma: it achieves 89.03\% personalization accuracy under extreme skew (+0.70\,pp over Ditto, +1.96pp over FedRep) at roughly half the memory footprint of dual-model Ditto (113.42 MB vs.\ 217.15 MB), while completely closing the split-head IID collapse (72.92\% vs.\ FedRep's 61.79\%) and improving tail-client fairness in most skewed regimes (+7.17\,pp over FedRep under severe skew; $-$2.56\,pp at extreme where FedRep retains narrow lead). On high-cardinality CIFAR-100 ($C=100$), HEP reaches 65.06\% personalized accuracy (+3.57\,pp over Ditto) and 50.17\% bottom-10\% fairness. We couple sketch routing (plaintext in prototype; SecAg-compatible) with sample-weighted aggregation, provide formal $(\epsilon,\delta)$-DP accounting on the clipped sketch when enabled, and show adaptive blending yields noise resilience. We release the full harness with operator self-verification, cross-backend consistency checks, per-run manifests, and programmatic significance testing to support reproducible edge-federated research.

\section{Reproducibility Protocol}
\label{app:reproducibility}

All experiments in the revised manuscript were executed through a single deterministic harness (\texttt{scripts/run\_comparison.py}) with the following guarantees:

\subsection{Device Verification and Cross-Backend Consistency}
The evaluation workstation pairs an AMD Radeon GPU with a CPU-only PyTorch build; acceleration is provided by a DirectX-backed backend whose operator coverage is incomplete (e.g., dimension-reduced median returns empty tensors, boolean advanced indexing is unsupported). We therefore (a) restricted all aggregation code to universally supported operators (sort-based statistics, integer \texttt{index\_select}/\texttt{index\_copy}), and (b) added a startup self-check that probes every accelerator-dependent operation used by the training and aggregation paths before accepting the device, falling back to CPU otherwise. An environment variable forces CPU execution for reference runs.

On an identical protocol (seed 42, CIFAR-10, ResNet-9, 15 clients, 10 rounds, $\alpha=0.5$), accelerated and CPU executions reached $76.07\%$ vs.\ $76.40\%$ final personalized accuracy ($0.33$\,pp delta; last-5 average delta $0.32$\,pp), confirming that hardware acceleration does not materially alter reported results.

\subsection{Evaluation-Interval Neutrality}
Metrics are evaluated every \texttt{eval\_interval} rounds plus the final round. Evaluation consumes no random numbers and mutates no model state; skipped rounds log rows without accuracy keys. Consequently this knob changes monitoring granularity only --- training trajectories are bit-identical regardless of its value.

\subsection{Hyperparameter Provenance}
Every non-standard constant in the released configuration carries a provenance annotation identifying the experiment that validated it. Key entries: dynamic anchor $a_i=\max(1/(2K),|\mathcal{Y}_i|/C)$ (default; fixed $a=0.15$ is the static-grid ablation in Table~\ref{tab:ablation}); eval temperatures $(T_l, T_p, T_r) = (0.6, 0.8, 1.0)$ (inference-only calibration; dynamic $T_{k,i}$ via logit dispersion $\mathrm{std}(z_{local})/\mathrm{std}(z_{root})$ is ablated but not default); cluster re-assignment triggers $\bar S < 0.30$ (mean directional stability $\bar S=\langle\cos(\Delta_{prev},\Delta_{curr})\rangle$), misalignment fraction $0.15$ (fraction of clients where best-other-cluster similarity exceeds own by $>0.15$); Two-Stage intra-round decoupling ($E\ge3$, $C\ge100$ collab then freeze) and staleness scale $\tau_{0}=4.0$ (or $\max(1,t/\text{participation\_count})\approx1/C_p$ when history available); variance-adaptive $\beta_{c,k}=V_k/(V_k+\|\Delta_k\|^2)\in[0.1,0.9]$ (static $\beta_c=0.70$ is the ablated baseline); local compute budget $E = 5$ epochs/client/round --- validated to match or exceed $E=10$ across IID and moderate-skew regimes at half wall-clock cost, keeping HEP's per-round client compute within $1.67\times$ of split-head baselines training $3$ epochs (FedRep 5 passes, Table~\ref{tab:hardware_footprint}). HEP is heuristic-free (no grid search) but not parameter-free (fixed $K=3$, $m=64$, $C_g=1.0$, $C_p$, etc.).

\subsection{Statistical Testing}
Headline multi-seed comparisons (Table~\ref{tab:main_benchmark} HEP/FedAvg/Local-Only/FedPer) use paired two-tailed $t$-tests across seeds {42, 123, 7} at $\alpha=0.05$ ($df=2$). Rows marked \S\ (APFL, Ditto, FedRep, FedBABU, FedALA, CFL) report single-seed canonical runs (seed~42) and are \emph{not} significance-tested against the multi-seed means; mechanism studies (Tables~\ref{tab:byzantine_multi_attack}--\ref{tab:clustering_privacy}) similarly use seed~42 with provenance in captions. Per-seed paired accuracies are retained by the harness, and the significance table is generated programmatically from raw artifacts rather than transcribed.

\subsection{Baseline Fidelity and Provenance}
\label{app:baseline_provenance}
Every competing method was audited against its canonical publication and re-validated inside the released harness; Table III rows are rendered programmatically from raw run artifacts:
\begin{itemize}
    \item \textbf{Ditto} \cite{li2021ditto}: the proximal term of the personalization objective anchors at the received global model $w^{(t)}$, matching the original formulation $\min_{w_p} \mathcal{L}(w_p) + \tfrac{\lambda}{2}\lVert w_p - w^{(t)} \rVert_2^2$. The penalty coefficient is fixed at $\lambda = 0.1$ for all clients and rounds (the per-client $\lambda_i$ selection heuristic of the original work is not reproduced), and both optimization legs share identical local hyperparameters. Historical byzantine-robustness configurations used $\lambda = 0.05$; all re-executed runs standardize on $\lambda = 0.1$.
    \item \textbf{APFL} \cite{deng2020adaptive}: independent dual models with decoupled global tracking and blended-gradient local updates per Algorithm~1 of the original paper; the mixing weight adapts by gradient descent with clamping to $[0.01, 0.99]$, and evaluation blends predictions with the learned weight.
    \item \textbf{FedRep} \cite{collins2021exploiting}: audited implementation with documented deviations (head-first/joint schedule; representation-only aggregation via head-coordinate masking; two guards vs.\ canonical: BatchNorm statistics paused during head-only phases, head-phase gradients clipped max-norm~1.0). FedRep receives exactly \texttt{local\_steps} local passes per round (5 passes in our setting via head+joint schedule, Table~\ref{tab:hardware_footprint}, vs.\ 3 passes for FedAvg/FedPer/FedBABU).
    \item \textbf{FedBABU} \cite{oh2021fedbabu}: canonical protocol --- the classification head stays frozen at each client's initial random initialization during all federated rounds (body-only gradients and uploads) and is trained exclusively at deployment time (\texttt{babu\_finetune\_steps} SGD steps on local training data before evaluation).
    \item \textbf{FedPer} \cite{arivazhagan2019federated}: joint training with a private final classification layer; all base layers aggregated.
    \item \textbf{FedALA} \cite{zhang2023fedala}: faithful port of the official Adaptive Local Aggregation module --- element-wise interpolation weights between the client's previous local model and the received global model are learned by gradient descent on sampled local data over the top two parameter tensors (sampling rate 80\%, $\eta = 1.0$), followed by standard local training and full-model upload.
    \item \textbf{CFL} \cite{sattler2020clustered}: server-side recursive separation driven by pairwise cosine similarities of client updates, with iterative refinement against cluster-mean update directions; the separation threshold $\epsilon$ starts high and is successively decreased until the first separation is observed, per the original tuning recipe.
\end{itemize}

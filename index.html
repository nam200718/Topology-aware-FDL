Why FedHEP? The Single-Backbone Multi-Tier Architecture

Personalized Federated Learning on edge devices faces an acute dilemma: dual-model frameworks (like Ditto) maintain two separate deep neural networks on each device (roughly doubling peak VRAM and latency), while decoupled split-head approaches (like FedRep) completely isolate edge clients from their peers, causing severe overfitting when local data is scarce.

FedHEP resolves this by training a single shared feature extractor feeding three linear classification heads: Root ($W_r$) for global consensus, Parent ($W_p$) for collaborative peer clusters, and Local ($W_l$) for private on-device adaptation.

Step 1: Broadcast & Model Dispatch (Downlink)

Concurrently, Cluster Heads send their collaborative Parent head $W_p$ exclusively to clients in their assigned peer cluster. Key Invariant: The client's Local head $W_l$ is never broadcast or received; it stays saved in the client's local memory from the previous round!

How Local Class Scarcity Dynamically Dictates Head Weights:

When $\alpha=0.05$ (Extreme Skew), an honest client possesses only 2-5 classes out of 100. Its label entropy drops to near zero, driving its skew metric $R_{\text{skew}} \to 0$. Under FedHEP's degree-2 Bernstein weighting, this shifts over 70% of model capacity into the Local and Parent heads to fit the client's narrow specialty, while the anchor floor $a_i = \max(1/(2K), |\mathcal{Y}_i|/C)$ preserves a guaranteed tie to global consensus. Under balanced IID ($\alpha=\infty$), $R_{\text{skew}} = 1.0$, seamlessly shifting 100% capacity into the Root head (Pure FedAvg)!

Active-Class Logit Masking (ACLM)

Applied on Parent & Local Heads

Shielding the shared convolutional backbone from gradient interference caused by absent categories.

Codebase Implementation src/core/loss.py:L11-26
❌ Problem / Flaw in Prior Work

Standard cross-entropy evaluates probabilities over all 100 classes. When an edge device only has 2 classes (e.g., Cat and Dog), standard cross-entropy penalizes all other 98 missing classes (e.g., Ship, Truck), pushing their logits toward negative infinity. This creates non-zero negative gradient updates that degrade the shared feature backbone, destroying shared representations.

⚙️ What It Does (Input → Operation → Output)

Input: Raw logit vector from Parent or Local head ($z \in \mathbb{R}^C$) and the client's observed class set $\mathcal{Y}_i$.
Operation: Replaces logits of all unobserved classes with $-10^9$ ($-\infty$) prior to computing softmax.
Output: Masked cross-entropy loss where missing classes evaluate to exactly zero probability ($\tilde{p}_c = 0.0$).

💡 Why It Works (Intuitive Rationale)

Because $\exp(-\infty) = 0$, missing classes receive zero probability. The backpropagated gradient with respect to class logit $c$ is $\tilde{p}_c - \mathbb{I}(y = c)$. For missing classes, $\tilde{p}_c = 0$ and the ground truth indicator is also $0$. Thus, $0 - 0 = 0.0$! Unobserved categories contribute exactly ZERO gradient into the shared backbone, completely shielding shared features without needing separate networks.

class ActiveMaskedCrossEntropyLoss(nn.Module):
    def __init__(self, mask_value: float = -1e9):
        super().__init__()
        self.mask_value = mask_value

    def forward(self, logits, targets, active_mask=None):
        if active_mask is not None:
            # Mask inactive classes to -1e9 so their softmax probability is 0
            logits = logits.masked_fill(~active_mask.to(logits.device), self.mask_value)
        return F.cross_entropy(logits, targets)
